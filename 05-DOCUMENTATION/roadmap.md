# برنامهٔ توسعه و دروازهٔ پذیرش

| مرحله | خروجی | پذیرش |
|---|---|---|
| ۰ — مبنا | ثبت دارایی، brief، PRD، معماری، طرح داده، نمونهٔ قابل اجرا | فایل‌ها و hash قابل وارسی؛ build و تست نمونه موفق |
| ۱ — هستهٔ آفلاین | SQLite بومی، migration، کالا/دسته/عکس/جست‌وجو، دفترکل انبار، قیمت گروهی و undo | آزمون atomicity و ۱۰هزار کالا؛ خاموشی ناگهانی باعث سند نیمه‌کاره نشود |
| ۲ — فروش و فاکتور | مشتری، پیش‌نویس، صدور/ویرایش نسخه‌دار/ابطال، شمارهٔ یکتا، انبار/پرداخت تراکنشی | reconciliation موجودی و جمع پول؛ تاریخچهٔ هر نسخه |
| ۳ — قالب و خروجی | پنج طرح قابل مقایسه، انتخاب طرح، ویرایش فیلدهای مجاز، A4 PDF/PNG رنگی/تک‌رنگ، چاپ و share | تأیید متن/فونت فارسی و آزمایش چاپگر رنگی و سیاه‌وسفید |
| ۴ — داده و پشتیبانی | CSV/XLSX، backup رمزدار/restore، SMS intent، صفحهٔ MAJORA | round-trip، فایل خراب، رمز غلط، import تکراری و لینک تماس تأییدشده |
| ۵ — انتشار | Android APK/AAB، راهنمای کاربر، سنجش عملکرد، accessibility و بازیابی | تست روی دستگاه ضعیف، چرخش صفحه، بزرگ‌نمایی متن، بدون اینترنت |

پیش از مرحلهٔ ۳ باید پرسش‌های فونت، متن حقوقی، هویت بصری و طرح فاکتور بسته شوند. پیش از انتشار، مالیات/«رسمی» بودن و سیاست چند دستگاه به تصمیم مستند نیاز دارند.
