# ساخت و نگهداری نسخهٔ Android

## هویت و امضا

- شناسهٔ ثابت برنامه: `ir.majora.classicbag`.
- نسخهٔ نامزد فعلی: `versionName=1.0.0` و `versionCode=2`. برای هر نسخهٔ قابل ارتقا، `versionCode` باید بزرگ‌تر شود.
- کلید پایدار PKCS#12 در `07-BACKUPS/android-signing/classicbag-release.p12` و گذرواژه در فایل خصوصی همان پوشه نگهداری می‌شود. کلید، گذرواژه و فایل‌های پشتیبان در `.gitignore` هستند و نباید در Git یا گزارش عمومی قرار گیرند.
- GitHub Actions چهار Secret با نام‌های `MAJORA_KEYSTORE_BASE64`، `MAJORA_KEYSTORE_PASSWORD`، `MAJORA_KEY_PASSWORD` و `MAJORA_KEY_ALIAS` دارد. محتوا در خروجی CI چاپ نمی‌شود. فایل محلی کلید را برای بازیابی در محل امن مستقل نگهداری کنید؛ Secretهای GitHub قابل خواندنِ مجدد نیستند.

## ساخت نسخهٔ بعدی

1. تغییرات سورس را با آزمون‌های مرتبط ثبت کنید. `npm test` و `npm run build` باید موفق باشند.
2. پیش از ساخت نسخهٔ جدید، `versionCode` را در `01-CORE-PLATFORM/apps/mobile/android/app/build.gradle` افزایش دهید و `versionName` را به‌روز کنید. شناسهٔ برنامه و کلید امضا را حفظ کنید.
3. workflow دستی `.github/workflows/android-release.yml` را از شاخهٔ `main` اجرا کنید. این workflow وابستگی‌ها را نصب می‌کند، تست می‌گیرد، وب را می‌سازد، Capacitor را همگام می‌کند، APK را با کلید پایدار امضا می‌کند و امضا، شناسه، شمارهٔ بیلد و SHA-256 را بررسی می‌کند.
4. اجرای امضاشده روی شبیه‌ساز و تصویر صفحهٔ آغازین را بررسی کنید. آزمون روی گوشی واقعی برای دوربین، چاپ، اشتراک، PDF چندصفحه‌ای، پشتیبان و بازیابی همچنان لازم است.
5. APK و گزارش آزمون را کنار سورس منطبق در `06-BUILDS-AND-RELEASES` نگهداری کنید. هش، گواهی امضا، `versionCode` و commit سورس را در گزارش همان نسخه بنویسید.

## نصب و ارتقا

روی گوشی، APK امضاشده را باز و نصب کنید. برای ارتقا، همان شناسه و همان کلید امضا و `versionCode` بالاتر لازم است. APKهای Debug با کلید متفاوت امضا شده‌اند و روی همان بسته به Release امضاشده ارتقا نمی‌یابند. پیش از حذف هر نصب دارای داده، از داده‌ها نسخهٔ پشتیبان تأییدشده تهیه کنید؛ پاک‌کردن برنامه دادهٔ محلی آن را حذف می‌کند.

## بازیابی داده

در تنظیمات برنامه، «ساخت ZIP رمزدار» پشتیبان SQLite، تصاویر و PDF فاکتورها را می‌سازد. برای بازیابی، همان ZIP و گذرواژه لازم است؛ برنامه داده را ابتدا در پایگاه دادهٔ جدا بررسی می‌کند و سپس به آن سوییچ می‌کند. این مسیر تا انجام آزمون روی دو گوشی و نسخه‌های قدیمی‌تر **تأیید تولیدی ندارد**. فایل ZIP رمزدار را همراه گذرواژه در دو جای مستقل و امن نگهداری کنید.
