# مرحلهٔ کنترل قابلیت‌های فروشگاه

این مرحله یکی از معیارهای [تحویل نهایی](FINAL-DELIVERY-GATES-2026-11-10.md) است و به‌تنهایی محصول را نهایی نمی‌کند.

## تغییرات اجراشده

- مالک MAJORA در «قابلیت‌های فروشگاه‌ها» برای هر فروشگاه ۱۳ بخش را جداگانه فعال/غیرفعال می‌کند. وابستگی‌ها قبل از ذخیره در رابط نشان داده می‌شوند و سرور پیکربندی ناسازگار را با 409 رد می‌کند.
- سیاست در رکورد همان فروشگاه ذخیره و در `tenant.features.update` ممیزی می‌شود. کلید نامعتبر رد می‌شود. همهٔ بخش‌ها برای فروشگاه‌های موجود پیش‌فرض فعال‌اند.
- فیلتر سروری همهٔ مسیرهای مربوط را پیش از اجرای endpoint می‌سنجد و برای بخش غیرفعال 403 می‌دهد؛ جست‌وجوی سراسری نیز آن نوع نتیجه را نشان نمی‌دهد. فروشگاه فقط سیاست خودش را می‌خواند و نمی‌تواند آن را تغییر دهد.
- منوی فروشگاه پس از دریافت سیاست ساخته می‌شود، هنگام بازگشت به تب نیز آن را تازه می‌کند و هر ۳۰ ثانیه بازخوانی می‌کند. هنگام خطای دریافت، صفحهٔ بازیابی و خروج نشان داده می‌شود.
- SQLite محلی ستون را بدون حذف داده اضافه می‌کند. migration SQL Server `TenantFeaturePolicy` و اسکریپت idempotent تولید شد.
- یک زیرپرس‌وجوی فهرست مرجوعی نیز برای دفاع بیشتر به TenantId محدود شد.
