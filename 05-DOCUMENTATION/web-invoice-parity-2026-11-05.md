# گام قابل بازبینی وب: قالب فاکتور فروشگاه کلاسیک

تاریخ: ۵ نوامبر ۲۰۲۶. وضعیت انتشار: **آزمایشی، غیرقابل عرضهٔ تجاری**. این گام فقط بخشی از فاصلهٔ وب با Android را پوشش می‌دهد. هیچ دادهٔ واقعی مشتری از گوشی منتقل نشده است.

## تغییر انجام‌شده

- تنظیمات نام، شعار، تماس، نشانی، کارت، شش بند شرایط، شناسه‌های اجتماعی و لوگو برای هر فروشگاه جدا ثبت می‌شود. مدیر هنگام ایجاد فروشگاه می‌تواند نمونهٔ تأییدشدهٔ «کیف و کمربند کلاسیک» را انتخاب کند؛ تصاویر اصلی بازنویسی نشده‌اند.
- قالب نمایش وب همان مؤلفهٔ React فاکتور اپ Android است. پیش‌نمایش A4/A5، رنگی/سیاه‌وسفید، متن قابل کپی و پنجرهٔ چاپ مرورگر دارد. خروجی PDF از قابلیت Save as PDF مرورگر وابسته به تنظیمات چاپگر/مرورگر است؛ تولید PDF یا PNG مستقل هنوز پیاده نشده است.
- نسخهٔ مشخصات برند و لوگو هنگام صدور در خود فاکتور ثبت می‌شود تا ویرایش بعدی تنظیمات فروشگاه، نمای فاکتور قدیمی را عوض نکند. ویرایش همزمان قالب با شمارهٔ نسخهٔ ناسازگار رد می‌شود.
- متن کپی فاکتور شماره، تاریخ شمسی، مشتری، اقلام، جمع، پرداختی، مانده و شمارهٔ کارتِ تنظیم‌شده را شامل می‌شود.

## مانع‌های مشخصِ «محصول نهایی قابل فروش»

1. وب هنوز جریان‌های اصلی Android مثل مرجوعی، چک و تصویر آن، ویرایش/بایگانی سند، افزایش قیمت گروهی، عکس کالا، تاریخچه، جست‌وجوی سراسری و راهنمای تعاملی را به‌طور کامل ندارد.
2. سامانهٔ حسابداری وب دفترکل دوبل و کنترل‌های مورد انتظار برای جایگزینی حسابدار ندارد؛ داشبورد فعلی برآورد ۳۰روزه است و مالیات/مرجوعی/ماندهٔ آغاز دوره را محاسبه نمی‌کند. مشاور هوش مصنوعی اختیاری و قاعده‌ای است، نه مدیر خودکار کسب‌وکار.
3. پیامک، اعلان عملیاتی، درگاه اشتراک، ابزار انتقال امن دادهٔ Android و آزمون همزمانی روی SQL Server واقعی انجام نشده‌اند.
4. آزمون امنیت مستقل، آزمون بار، چاپ/PDF فیزیکی، بازیابی دیتابیس و اجرای واقعی روی میزبان .NET ایرانی انجام نشده‌اند.

تا بسته شدن این موارد، استفاده از این خروجی فقط در محیط آزمایشی و با دادهٔ ساختگی مجاز است. راه‌اندازی Production نیازمند تکمیل و شواهد آزمون‌های [راهنمای استقرار](web-deployment.md) است.
