# ادامهٔ اجرای MAJORA SaaS — ۱۰ نوامبر ۲۰۲۶

این سند وضعیت واقعی سورس و نصب محلی ویندوز را ثبت می‌کند. نسخه هنوز برای فروش یا استقرار روی سرور مشتری تأیید نشده است.

## تغییرات این مرحله

- **اشتراک:** پلن با توضیح و فهرست امکانات از پنل ماژورا تنظیم می‌شود. کد تخفیف درصدی با بازهٔ اعتبار شمسی در UI و زمان UTC در سرور ثبت می‌شود. قیمت نهایی دوباره در سرور محاسبه و با مبلغی که فروشگاه پیش از واریز دیده تطبیق داده می‌شود. سفارش کارت‌به‌کارت دارای کلید تکرارنشدنی، تصویر رسید محدود به JPEG/PNG/WebP و وضعیت مستقل «در انتظار تأیید/تأیید/رد» است. پس از تأیید دستی، اشتراک یک‌ماهه ساخته می‌شود؛ تأیید تکراری رد می‌شود. شماره کارت ماژورا از پنل مدیر تنظیم می‌شود. درگاه آنلاین هنوز متصل نیست و رابط کاربری آن را فعال نشان نمی‌دهد.
- **کاربران و ممیزی:** فهرست واقعی تمام کاربران در پنل ماژورا با شمار داشبورد تطبیق می‌شود. مالک، همکاران فروشگاه خود را می‌بیند؛ نام کاربری آنان را تغییر می‌دهد یا رمز موقت جدید تعیین می‌کند. تغییر نام یا رمز، نشست‌های قبلی همان کاربر را باطل می‌کند. رمز فعلی هیچ‌جا بازیابی یا نمایش داده نمی‌شود. صد رویداد اخیر با نام کاربری عامل در پنل مالک و مدیر ماژورا دیده می‌شود؛ همکار عادی اجازهٔ خواندن آن را ندارد.
- **خرید و انبار:** در فرم خرید می‌توان کالای جدید را با نام، شناسه، دسته و قیمت فروش ساخت. ایجاد کالا، ثبت خرید، بهای خرید و افزایش موجودی در یک تراکنش قرار دارند. شناسهٔ تکراری رد می‌شود.
- **مرجوعی:** قلم بدون شناسهٔ کالا به‌صورت پیش‌فرض بدون بازگشت به انبار مرجوع می‌شود و UI علت را توضیح می‌دهد. انتخاب بازگشت به انبار فقط برای کالای متصل به انبار ممکن است.
- **مشتری:** آدرس، شغل، نحوهٔ آشنایی، شمارهٔ معرف و یادداشت اختیاری در فرم جداشوندهٔ مشتری ثبت و ویرایش می‌شوند؛ زمان صدور فاکتور به این فیلدها وابسته نیست. وضعیت تسویه/مانده/چک برگشتی در فهرست مشتریان از فاکتورها و چک‌ها محاسبه می‌شود. CSV ستون شمارهٔ ردیف دارد.
- **خروجی Excel:** خروجی `.xlsx` مستقل از CSV با ستون‌های جداگانهٔ شمارهٔ ردیف، نام، تلفن و اطلاعات اختیاری ساخته می‌شود. شماره‌های تلفن به‌صورت متن ذخیره می‌شوند تا صفر آغازین حفظ شود؛ برگه راست‌به‌چپ و دارای سطر عنوان ثابت و فیلتر است. مقدارهایی که با `=` شروع می‌شوند سلول فرمول نمی‌سازند. آزمون HTTP فایل واقعی را باز کرد و ساختار XML آن، جداسازی فروشگاه، عنوان‌ها، شماره ردیف و نوع سلول تلفن را بررسی کرد.
- **نشان پرداخت:** فهرست مشتریان، انتخاب مشتری هنگام فروش، بازبینی فروش، فهرست فاکتورها، انتخاب فاکتور مرجوعی و فاکتورهای بایگانی‌شده برچسب متنی و رنگی وضعیت را کنار نام نشان می‌دهند. انتخاب مشتری از API وضعیت تجمیعی محاسبه‌شده استفاده می‌کند. پوشش برچسب تجمیعی هنوز شامل مشتریان بایگانی‌شده و سابقهٔ مرجوعی نیست.
- **ماژورا:** صفحهٔ پشتیبانی و معرفی با لینک قابل کلیک `majoraapp.ir`، تلفن‌ها و اینستاگرام به منوی وب افزوده شد.
- **یکسانی داده:** فروش خالص، مطالبات و بازپرداخت باز از محاسبهٔ مشترک برای داشبورد، حسابداری و مشاور می‌آیند.

### به‌روزرسانی خروجی Excel و نشان پرداخت

پس از تغییرات بالا، API و وب دوباره در حالت Release ساخته شدند؛ ۳۴ آزمون واحد و سناریوی یکپارچهٔ ۲۰ فروشگاه گذشت. آزمون جدید فایل XLSX را از API گرفت، بستهٔ ZIP و XML برگه را باز کرد و ستون‌های مستقل، ردیف، شمارهٔ تلفن متنی، نبود فرمول، راست‌به‌چپ بودن و جداسازی فروشگاه را بررسی کرد. بستهٔ ویندوز منتشرشده نیز روی پورت جداگانه سلامت API و صفحه را پاسخ داد.

پیش از به‌روزرسانی نصب محلی، پشتیبان سازگار SQLite در `07-BACKUPS/MAJORA-local-pre-xlsx-14050818-235504.db` گرفته شد و `integrity_check=ok` بود. نصب محلی بدون تعویض پایگاه داده به‌روز شد؛ سپس `http://127.0.0.1:5188/` پاسخ `200` و سلامت API پاسخ `ok` داد. یکپارچگی دیتابیس پس از اجرا `ok` و بررسی کلیدهای خارجی بدون خطا بود. SHA-256 فایل DLL نصب‌شدهٔ تازه: `DA20DECDB8AFB34B7C22B397E3262E6714C24702D585028B83773C75C654914A`.

دو migration تازهٔ `SubscriptionCheckout` و `CustomerProfile` برای SQL Server ساخته شدند. اسکریپت تغییر SQL Server در محیط توسعه تولید شد، ولی روی SQL Server واقعی اجرا نشده است. دیتابیس SQLite محلی موجود که با `EnsureCreated` ساخته شده بود، پس از پشتیبان‌گیری و توقف فرایند، با ساختار SQLite متناظر به‌صورت تراکنشی ارتقا یافت. نصب محلی اطلاعات کارت ماژورا را خالی نگه می‌دارد تا مالک مقدار واقعی را در پنل خود ثبت کند.

## موارد باقی‌مانده و مانع تحویل تجاری

1. درگاه پرداخت آنلاین و بازگشت معتبر از درگاه بدون انتخاب ارائه‌دهنده، قرارداد و اعتبارنامهٔ واقعی قابل فعال‌سازی نیست. کارت‌به‌کارت با تأیید دستی اجرا شده، اما واریز واقعی و تشخیص اصالت رسید در این محیط آزمون نشده است.
2. اتصال واقعی پنل پیامک و اعلان بله، ارسال OTP و بازیابی رمز با پیام، و صف/گزارش تحویل هنوز پیاده نشده‌اند؛ ارائه‌دهنده و اعتبارنامه لازم است. از ارسال موفق هیچ ادعایی نمی‌شود.
3. خروجی XLSX واقعی تولید و ساختار آن آزموده شد؛ بازکردن بصری فایل در Microsoft Excel روی سیستم کاربر هنوز آزمون نشده است.
4. وضعیت تجمیعی مشتری در فهرست و انتخاب فروش و وضعیت هر فاکتور در فهرست‌ها و انتخاب مرجوعی نشان داده می‌شود؛ نمایش وضعیت تجمیعی مشتری در همهٔ نماهای بایگانی و سابقهٔ مرجوعی هنوز کامل نیست.
5. مرورگر واقعی بعد از نصب تازه صفحهٔ ورود را نشان داد. ورود با حساب واقعی، بازبینی فرم‌ها در موبایل/دسکتاپ و پرداخت واقعی انجام نشده‌اند. آزمون API موقت جای آن‌ها را نمی‌گیرد.
6. Wizard ساخت فروشگاه، مدل کامل وضعیت سه‌گانه، ثبت دستگاه‌ها، نقش‌های کامل، آزمون SQL Server، بازیابی پشتیبان سرور و آزمون فشار/امنیت همچنان باز هستند. بنابراین این نسخه برچسب «نهایی و قابل فروش» ندارد.

برای ارتقای سرور، ابتدا از دیتابیس SQL Server و کلیدهای Data Protection پشتیبان بگیرید، migrationهای جدید را روی نسخهٔ جداگانه بیازمایید، و فقط پس از آزمون بازیابی و مسیر خرید واقعی منتشر کنید. فایل‌های دیتابیس محلی و پشتیبان در Git قرار نگرفته‌اند.

## ادامهٔ کد و بستهٔ نامزد — ۱۰ نوامبر

پس از گزارش بالا، تغییرهای زیر در سورس انجام شد:

- پیش‌نمایش فاکتور دریافت قالب و سند را مستقل انجام می‌دهد و در خطا امکان تلاش مجدد دارد. با این حال بازبینی بصری خروجی PDF/PNG و چاپ روی دستگاه هنوز انجام نشده است.
- مالک فروشگاه می‌تواند تلفن، نشانی، شماره کارت، شرایط و حداکثر چهار راه ارتباطی پایین فاکتور را تغییر دهد. نام، لوگو و شعار اصلی در سرور قفل می‌مانند. نسخه و ممیزی تغییرات ثبت می‌شود. چهار پلتفرم Telegram، Instagram، WhatsApp و X نشان SVG دارند؛ نشان اختصاصی سایر گزینه‌ها هنوز کامل نیست.
- ورودی مشترک ریالی با گروه‌بندی سه‌رقمی و مقدار آغازین خالی در فرم‌های اصلی فروش، کالا، خرید، چک، هزینه، پرداخت و اشتراک استفاده می‌شود. منطق قالب و نشانگر با آزمون واحد بررسی شد؛ آزمون تایپ در مرورگر واقعی باز است.
- شمارهٔ تماس مشتری و معرف در سرور و فرم با پذیرش ارقام فارسی/عربی و حفظ صفر اول اعتبارسنجی می‌شود. برای پرونده‌های قدیمی با شمارهٔ نامعتبر، ویرایش بعدی نیازمند اصلاح شماره است.
- جست‌وجوی تاریخچهٔ فعالیت در سرور روی کل رویدادهای مجاز انجام می‌شود؛ نقش و جزئیات رایج در UI فارسی‌تر شده‌اند. رویدادهای مالی برای حفظ قابلیت رسیدگی خودکار حذف نمی‌شوند.
- فرم‌های دسته‌بندی کالا/افزایش قیمت و صفحهٔ معرفی ماژورا بهبود یافته‌اند؛ نشان کامل ماژورا از دارایی موجود کپی شد و فایل اصلی تغییر نکرد.

### اصلاح خطای ارتباط و بستهٔ تازه‌تر

صفحهٔ ورودِ تب مرورگرِ باز، هنگام نبود API پیام خام `Failed to fetch` نشان می‌داد. پیام فارسی شامل علت احتمالی و امکان تلاش دوباره در لایهٔ مشترک درخواست اضافه شد. آزمون واحدِ قطع ارتباط موفق بود؛ اکنون ۳۹ آزمون در ۹ فایل می‌گذرند. ساخت وب و آزمون اجرای بستهٔ ویندوز با دیتابیس موقت نیز موفق بودند. نشانی توسعهٔ `127.0.0.1:5173` از ویندوز در دسترس نبود، بنابراین ظاهر تازهٔ این پیام در آن تب تأیید نشد.

آخرین بستهٔ نامزد: `06-BUILDS-AND-RELEASES/MAJORA-web-win-x64-20261110-network-candidate.zip` با SHA-256 برابر `328C187433478C70B9A7C976C601434E4E3E01672AB32E1A5EEEE64684F3C0E9`. بستهٔ قبلی در جدول بالا قدیمی‌تر است. هیچ‌کدام جایگزین نصب محلی دارای داده نشده‌اند.
