# ادامهٔ اجرای MAJORA SaaS — ۱۰ نوامبر ۲۰۲۶

این سند وضعیت واقعی سورس و نصب محلی ویندوز را ثبت می‌کند. نسخه هنوز برای فروش یا استقرار روی سرور مشتری تأیید نشده است.

## تغییرات این مرحله

- **اشتراک:** پلن با توضیح و فهرست امکانات از پنل ماژورا تنظیم می‌شود. کد تخفیف درصدی با بازهٔ اعتبار شمسی در UI و زمان UTC در سرور ثبت می‌شود. قیمت نهایی دوباره در سرور محاسبه و با مبلغی که فروشگاه پیش از واریز دیده تطبیق داده می‌شود. سفارش کارت‌به‌کارت دارای کلید تکرارنشدنی، تصویر رسید محدود به JPEG/PNG/WebP و وضعیت مستقل «در انتظار تأیید/تأیید/رد» است. پس از تأیید دستی، اشتراک یک‌ماهه ساخته می‌شود؛ تأیید تکراری رد می‌شود. شماره کارت ماژورا از پنل مدیر تنظیم می‌شود. درگاه آنلاین هنوز متصل نیست و رابط کاربری آن را فعال نشان نمی‌دهد.
- **کاربران و ممیزی:** فهرست واقعی تمام کاربران در پنل ماژورا با شمار داشبورد تطبیق می‌شود. مالک، همکاران فروشگاه خود را می‌بیند؛ نام کاربری آنان را تغییر می‌دهد یا رمز موقت جدید تعیین می‌کند. تغییر نام یا رمز، نشست‌های قبلی همان کاربر را باطل می‌کند. رمز فعلی هیچ‌جا بازیابی یا نمایش داده نمی‌شود. صد رویداد اخیر با نام کاربری عامل در پنل مالک و مدیر ماژورا دیده می‌شود؛ همکار عادی اجازهٔ خواندن آن را ندارد.
- **خرید و انبار:** در فرم خرید می‌توان کالای جدید را با نام، شناسه، دسته و قیمت فروش ساخت. ایجاد کالا، ثبت خرید، بهای خرید و افزایش موجودی در یک تراکنش قرار دارند. شناسهٔ تکراری رد می‌شود.
- **مرجوعی:** قلم بدون شناسهٔ کالا به‌صورت پیش‌فرض بدون بازگشت به انبار مرجوع می‌شود و UI علت را توضیح می‌دهد. انتخاب بازگشت به انبار فقط برای کالای متصل به انبار ممکن است.
- **مشتری:** آدرس، شغل، نحوهٔ آشنایی، شمارهٔ معرف و یادداشت اختیاری در فرم جداشوندهٔ مشتری ثبت و ویرایش می‌شوند؛ زمان صدور فاکتور به این فیلدها وابسته نیست. وضعیت تسویه/مانده/چک برگشتی در فهرست مشتریان از فاکتورها و چک‌ها محاسبه می‌شود. CSV ستون شمارهٔ ردیف دارد.
- **ماژورا:** صفحهٔ پشتیبانی و معرفی با لینک قابل کلیک `majoraapp.ir`، تلفن‌ها و اینستاگرام به منوی وب افزوده شد.
- **یکسانی داده:** فروش خالص، مطالبات و بازپرداخت باز از محاسبهٔ مشترک برای داشبورد، حسابداری و مشاور می‌آیند.

## شواهد اجرا

| بررسی | نتیجه |
|---|---|
| ساخت .NET | موفق، صفر هشدار و خطا |
| ساخت React/TypeScript | موفق؛ هشدار اندازهٔ بستهٔ اصلی باقی است |
| آزمون API با SQLite موقت | موفق: ۲۰ فروشگاه، سفارش و تخفیف، تصویر رسید، تأیید، تکرار درخواست، جداسازی فروشگاه، کاربران و ممیزی، مرجوعی، خرید کالای جدید، پروندهٔ مشتری و مسیرهای قدیمی |
| تست کد | ۳۴ آزمون در ۶ فایل، موفق |
| بستهٔ Windows | فایل منتشرشده روی پورت آزمایشی اجرا شد؛ API سلامت و صفحه پاسخ دادند |
| نصب محلی | `%LOCALAPPDATA%\MAJORA\LocalWeb\app`؛ `http://127.0.0.1:5188/`، سلامت API `ok` و صفحه `200` |
| دادهٔ نصب محلی | پشتیبان آنلاین پیش از ارتقا: `07-BACKUPS/MAJORA-local-pre-subscription-customer-20261110.db`، `integrity_check=ok`؛ پس از ارتقا تعداد ۴ کاربر، ۲ فروشگاه، ۲ پلن، ۱ مشتری و ۱ فاکتور حفظ شد؛ `integrity_check=ok` و `foreign_key_check` بدون خطا |
| همسانی نصب | SHA-256 فایل `Majora.WebApi.dll` نصب‌شده و منتشرشده: `55790EA5B758DA697CB7FD13C8A6A6786231492AB26751F76EB69D63A18AF7C7` |

دو migration تازهٔ `SubscriptionCheckout` و `CustomerProfile` برای SQL Server ساخته شدند. اسکریپت تغییر SQL Server در محیط توسعه تولید شد، ولی روی SQL Server واقعی اجرا نشده است. دیتابیس SQLite محلی موجود که با `EnsureCreated` ساخته شده بود، پس از پشتیبان‌گیری و توقف فرایند، با ساختار SQLite متناظر به‌صورت تراکنشی ارتقا یافت. نصب محلی اطلاعات کارت ماژورا را خالی نگه می‌دارد تا مالک مقدار واقعی را در پنل خود ثبت کند.

## موارد باقی‌مانده و مانع تحویل تجاری

1. درگاه پرداخت آنلاین و بازگشت معتبر از درگاه بدون انتخاب ارائه‌دهنده، قرارداد و اعتبارنامهٔ واقعی قابل فعال‌سازی نیست. کارت‌به‌کارت با تأیید دستی اجرا شده، اما واریز واقعی و تشخیص اصالت رسید در این محیط آزمون نشده است.
2. اتصال واقعی پنل پیامک و اعلان بله، ارسال OTP و بازیابی رمز با پیام، و صف/گزارش تحویل هنوز پیاده نشده‌اند؛ ارائه‌دهنده و اعتبارنامه لازم است. از ارسال موفق هیچ ادعایی نمی‌شود.
3. خروجی CSV شماره ردیف و ستون‌های مجزا دارد، اما خروجی XLSX واقعی و آزمون Excel فارسی/شماره‌های دارای صفر ابتدایی هنوز باز است.
4. وضعیت مشتری در فهرست مشتریان نشان داده می‌شود؛ نمایش همان برچسب در همهٔ نماهای فاکتور و فروش هنوز یکپارچه نشده است.
5. مرورگر واقعی بعد از نصب تازه صفحهٔ ورود را نشان داد. ورود با حساب واقعی، بازبینی فرم‌ها در موبایل/دسکتاپ و پرداخت واقعی انجام نشده‌اند. آزمون API موقت جای آن‌ها را نمی‌گیرد.
6. Wizard ساخت فروشگاه، مدل کامل وضعیت سه‌گانه، ثبت دستگاه‌ها، نقش‌های کامل، آزمون SQL Server، بازیابی پشتیبان سرور و آزمون فشار/امنیت همچنان باز هستند. بنابراین این نسخه برچسب «نهایی و قابل فروش» ندارد.

برای ارتقای سرور، ابتدا از دیتابیس SQL Server و کلیدهای Data Protection پشتیبان بگیرید، migrationهای جدید را روی نسخهٔ جداگانه بیازمایید، و فقط پس از آزمون بازیابی و مسیر خرید واقعی منتشر کنید. فایل‌های دیتابیس محلی و پشتیبان در Git قرار نگرفته‌اند.
